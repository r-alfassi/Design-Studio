# Purpose

This file says why the project exists, the main problem it answers, how it answers it, and where it is headed. Everything else in the record answers to it.

## Why it exists

Design Studio holds reusable design craft for the Designer, Principal, and their projects. It keeps cross-project design procedures, deliverable formats, reasoning frameworks, standards, references, and external library pointers separate from any one client engagement.

Design Studio also carries the Designer's process for the visual phase, which starts once a project's direction is stated and happens in a Figma file. The Designer and the agent collaborate there until the design is aligned, formalize what should become part of the design system, and prepare the design so that production can take it from there. Visual work done directly in a product's code is not part of this process.

## The main problem

Design craft scattered through client work or individual projects must be rediscovered or copied before another project can use it. Copying it also risks carrying client-specific material into a reusable resource, so projects lose both accumulated practice and a clear boundary around it.

## How it answers the problem

Design Studio classifies reusable design material by what it does, keeps it discoverable, and has a project select only the smallest relevant resident. Each project keeps its own product and implementation decisions; Design Studio supplies reusable craft rather than deciding a case.

## Where it is headed

Toward a durable, client-neutral design-craft resource that compounds from real project use while remaining small enough to navigate and apply on demand.
