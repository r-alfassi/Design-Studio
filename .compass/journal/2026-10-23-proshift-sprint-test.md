# First test of the narrowed studio on ProShift

Observed 2026-10-23 on ProShift (a Hebrew, right-to-left scheduling app), after the studio was narrowed to work in a Figma file (Q-68). The Designer set the test as: can the studio run the design workflow they envisioned. This entry is evidence for R-21, R-32 and R-34, for the frame card and for the `rtl` and sprint skills. It governs nothing.

What worked: the spine found the stated direction, found the project's Figma file, offered a `DESIGN.md` and waited. The sprint was scoped to the three open points on the schedule screen. The kit's direction summary and placeholder box imported by key into a file that had not added the library.

What it found:

- **The frame card could not hold a design.** Its slot was an ordinary frame, and the Plugin API refuses to add children inside an instance. The slot was replaced with a native slot (`component.createSlot()`, not `figma.createSlot()`). It needs the Designer's republish before another file sees it.
- **The capture of a right-to-left page is mirrored.** The captured frames are horizontal auto-layout in DOM order, left to right, so the logo, step 1, the table's label column and the title are on the wrong side. The browser render of the same page is correct. The agent copied the capture's order into two proposals and described the left-to-right days as v8's behaviour, which was wrong. Fixed by reversing rows and swapping start and end alignment on a clone, and both proposals were mirrored the same way. The lesson now sits in the sprint skill and the `rtl` skill's Figma reference. R-34 was added.
- **A hidden `position: fixed` toast is captured as an empty frame**, which showed as a dark pill in the middle of the page.
- **`DESIGN.md` missed four colors** that v8 hardcodes (the amber tint, its ink, its rule, and the dark step-number fill). They are in the Figma tokens and should be added to `DESIGN.md`.
- **A script that sets `FILL` before a node has a parent fails** and leaves half-built nodes on the page. The retry removes page-level orphans first.
- **After the republish the sprint section built as designed.** The baseline clone and both proposals sit in frame cards with state labels, and `tools/check-presentation-chrome.js` ran on the ProShift page with no findings (it resolved the library's `surface/sunk` variable as "Studio · Color"). Its name list was missing the new kit components and was extended.
- **The audit script called all slotted content component-owned.** `inspect.js` walks up to a remote instance, and a design in a frame card's slot has one as an ancestor. The walk now stops at a slot. Run on the two proposals it found row cells overflowing the table by 3px (fixed by making the cells fill the row), 14 deliberately empty role-row cells per proposal (left, as removing them needs the Designer's yes), and the popover's default pin (left, it is an overlay).
- **The first sprint carried three concerns.** It compared unfilled slots, the rest-ratio panel and a week-change question at once, and the Designer could not focus on any one. It was cut to the unfilled slots: both proposals now keep the v8 rest-ratio panel, the popover, the settings button, the chip and the open-question placeholder were removed, and the other two concerns stay as proposals and an open question on the flow page, to become their own sprints after this one decides. The sprint skill now says one concern per sprint (R-35). The agent should have caught it when it wrote the direction summary, since the "change being tested" line needed an "and".
- **A hug-width row in a vertical frame sat on the left of an RTL card.** The stat tiles and station tabs were packed to the left edge of the schedule card, where the real app starts them on the right. Fixed by making each fill the width and packing to the right end. The measurement showed the card itself centered, so the Designer's report ("the schedule card is aligned to the left") was the row inside it. The `rtl` skill's Figma reference now names the case.
- **Closing a sprint ran end to end.** The Designer picked Proposal A. B was labelled not chosen, A became the Final outcome at the far right, the review was recorded in a kit callout beside the summary (components: no update; flows: the flow box marked agreed), and a design-debt row was written in the project. The expanded state of A's banner had not been designed, which only showed up when writing the row's status.
- **Sprint 02 followed from Sprint 01.** Its baseline is the Sprint 01 outcome, cloned, and its proposals differ from it only in the rest-ratio control.

## Formalizing the ProShift design system (same day)

The Designer asked to step back and formalize the existing system, so the formalize skill ran on ProShift with the captured frames as the source.

- **Which side is newer:** the code. Figma had no components, and the tokens made earlier the same day were read from the stylesheet. The sprint outcomes were ahead of the code and already had a debt row.
- **Extraction on four captured frames (795 nodes):** 17 decimal font sizes from rem conversion, 20 spacing values with many odd ones, 14 radii, 0.8px strokes on 211 nodes (a capture leftover for 1px), 8 colors outside the documented palette, and 37 text nodes in Arial. The Arial is real: the step pills and the ×, → and ← buttons are native buttons that do not inherit the font, so v8 renders them in Arial, a production bug. The Designer approved the proposal as written, which moved it to Heebo.
- **Foundations created:** 46 variables in three collections, 8 text styles, 5 effect styles, all with explicit scopes and CSS names, documented on a Foundations page built only from kit pieces.
- **A text style mismatched the capture.** Letter spacing of 0.5px had been put on the 12px bold Label style, but only 7 of about 35 uses had it, so it was removed.
- **The kit's Component container had the Frame card's flaw.** Its preview, anatomy and do and don't areas were plain frames, which the Plugin API will not add children to inside an instance. They are now bound to slot properties, and the anatomy and do and don't areas, which had been 590px wide inside a 514px column, now fill the width. It needs the Designer's republish before another file sees it.
- **Main components cannot live in a container.** A main component cannot sit inside an instance, so the formalize skill now says main components stay at page level and the container's preview holds instances of the variants.
- **First component:** the Button, with kind, size and state variants, bound to the new tokens. The remaining atoms, molecules and organisms wait for the Designer's look at it.
- **Emoji icons became real icons, from an existing library.** The Designer approved replacing them. The libraries in the file did not have an icon set: the Material 3 kit exposed only `person` and a few others its own components use, and the Simple Design System had lock variants only. The five needed icons came from Lucide (ISC, v0.469.0) as an Icon component set of six editable vectors, stroked with a token. The formalize skill now says this order.
- **Second design-debt row:** v8's step pills and small buttons render in Arial because native buttons do not inherit the font.
- **The formalize run reached the whole system.** Besides the Button and the Icon set, 33 more components were built from the stylesheet and the four captures, mirrored to right to left: 17 atoms, 10 molecules and 7 organisms, all built from instances of the lower layer and bound to the tokens. A component audit of 422 nodes found one raw value (a 12px padding, then bound), no default layer names, no missing main components, and 12 deliberately hidden icon layers.
- **The stylesheet showed what the captures did not.** The shift cell has four states and the orange preference warning uses two colors that no captured frame showed. The formalize skill now says states come from the stylesheet as well as the capture.
- **The shared text property bug happened a third time** (Callout, then Tag, Badge and Status). It is now a rule in the formalize skill. A component also cannot contain a component, which broke the first Step pill build.
- **A screen built only from instances matched the original.** The Sprint 01 schedule screen was composed from the new components in order, in one pass, and the screenshot matches the frame row for row. The presentation-chrome check ran on the Design system and Foundations pages with no findings.
- **Not formalized:** the expanded state of the Unfilled banner (not designed), the availability modal and any hover or drag state no screen showed. The Stations editor was built from the capture and the stylesheet's layout, and has not been checked against a browser render of an open station.
- **The Designer saw the components as one undivided pile.** The documentation page had Atoms, Molecules and Organisms sections, but the page holding the main components had 35 loose items. They were grouped into three sections in the same order, and the formalize skill now says so. The first pass should have grouped them when it classified them (step 6).
- **Two pages for one system competed.** After grouping, the Designer pointed out that the components page and the documentation page showed the same 34 components in two places. The split existed because a main component cannot sit inside a container's slot, so the container can only show copies. The Designer chose one page, divided into sections by layer, with each main component beside its container. `standards/studio-presentation.md` now says so, the chrome check accepts a main component whose name matches a container in the same section, and the old page was removed once it held only empty sections. An earlier count of 35 components was a miscount: the system has 34 (17 atoms, 10 molecules, 7 organisms).
- **A screenshot helper left a duplicate section.** To look at the Atoms section, the agent cloned it into a temporary frame, took the picture and removed the frame. A section cannot live inside a frame, so the clone stayed on the page at the same position as the original, with 35 copies of containers and components that overlaid the real ones as faint doubles. The Designer asked what the ghosts were. It was found by counting: 52 containers where there should be 34. The agent confirmed that all copies had a different id prefix and that nothing outside them pointed at their components, then removed only that section with the Designer's yes. Rule for the agent: look at a node with a screenshot of its id and never clone it to frame it, and count containers and components after any restructure.
- **The Designer wanted no copies at all.** Even with one page, each component appeared twice: as instances in its container and as the main component beside it. The Designer asked to drop the copies from the card and to give each component a section holding the card and the component. Done for all 34: 34 preview wrappers with 332 instances were removed, each container's preview is hidden, and each component has a nested section of its own. The Designer's attempt to place a main component inside the slot did not work for them, and through the Plugin API a main component cannot be placed in a slot, so the main component sits beside the card. The standard and the formalize skill follow, and the chrome check passes on all 37 sections.
- **A frame is a better group than a section.** The Designer proposed a plain auto-layout frame per component in place of a nested section, because the layout direction then becomes a setting. The 34 sections were replaced (and removed once empty), horizontal in Atoms and Molecules and vertical in Organisms, with the gap bound to a kit spacing variable. The standard now lets a fill-less, stroke-less, effect-less auto-layout frame group a container with its component, and the chrome check reads its children as the section's own. The ProShift `DESIGN.md` and `DESIGN-DEBT.md` were committed locally and not pushed.
- **One card per component.** The Designer asked for each group to read as a single card: vertical, with the group's fill and border carrying the look and the spec card inside losing its own. The agent explained the intention first and listed what would change in the standard, then did it for the 34 groups: kit panel fill, rule border, hairline weight, small radius and spacing, all bound to kit variables, groups packed into rows. The standard now allows a group frame whose fill, stroke and radius are kit variables, and the one override of a kit instance, the spec card's fill and border turned off inside such a group. The loose container `70:5046` was removed with the Designer's yes.
- **A kit card cannot hold the main component, so the kit got a switch instead.** The agent had offered a "component spec" kit card that would hold both the description and the component. Tested before building: Figma refuses a main component inside a kit instance's slot, and inside a frame in the slot, so no kit component can hold it and the group frame stays a frame bound to kit variables. The agent said so and offered the one real improvement: a Framed switch on the Component container, which removes the only override the standard allowed. The Designer agreed and republished. The 34 instances still pointed at the older copy of the container in the file, so each was swapped to the latest version and set to Framed off. A library update does not reach existing instances by itself.
- **One page, two groups.** The Foundations page was merged into the Design system page: a Primitives section (Color, Type, Space, Shape, Effects, side by side) above a Components section (Atoms, Molecules, Organisms, side by side), each with a kit section header, and the empty Foundations page was removed. The chrome check passes on 10 sections, 34 groups and 358 instances.
- **Sprint 02 closed on the rest-ratio chip.** The Designer chose Proposal B (a toolbar chip that opens a popover) on 2026-10-25. The close ran the same way as Sprint 01 and needed no change to the skill: A labelled not chosen, B the Final outcome at the far right, the promotion review recorded in a kit callout (components: a chip and a popover are new and wait for a formalize decision; flows: the flow box marked agreed), a design-debt row written, and the Sprint 01 row's dependency on Sprint 02 removed. The second run is evidence that closing a sprint is repeatable. Its frames were cloned from Sprint 01's outcome and were built before the design system existed, so they are plain frames and not instances of the components.
- **A sprint outcome was formalized through the design system.** After Sprint 02, the Designer said yes to formalizing the chip and the popover. The formalize skill ran in a short form, since the outcome used only existing tokens and parts: a Rest ratio chip (atom) and a Popover (molecule, with Content and Actions slots, the first in-file component to use slots) were built from the sprint frame, bound to the tokens, and documented in groups. The check on the two found no raw value, no default name and no hidden layer. The composed schedule screen on the Screens page was updated to the two agreed outcomes by swapping one instance. The page now holds 36 components and 364 instances, with no finding from the chrome check. The path from sprint outcome to component to composed screen took no new rule.
