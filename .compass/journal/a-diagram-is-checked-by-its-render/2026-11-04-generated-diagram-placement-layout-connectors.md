# A generated diagram looked finished before it was

Observed 2026-11-04, in a Figma MCP session where one agent drew four flowcharts on a FigJam study board for the Designer: two alternative ways of working and the decision gate that chooses between them, one of them redrawn twice. The Designer had named the page to draw on. This entry is evidence for a possible check on generated diagrams (Q-69). It governs nothing.

What got through, and what the agent's own checks missed:

- **The diagram went to a different page from the one asked for.** The Designer's link pointed at an empty page of a board with two pages. The diagram tool takes a file and no page, so it wrote to the first page, appended at the far right of the existing work. The Figma plugin's FigJam skill says a FigJam file has a single page, and the agent had not listed the pages first. It found out by reading the first page after the first diagram. Moving the nodes across by script worked. The agent probed it first with a throwaway sticky, then moved 31 nodes chosen by two independent selectors that had to agree, and the 123 existing nodes were untouched.
- **Shifting the moved nodes toward the page origin stretched nine of seventeen connectors** to about 18,000 px, because a connector attached to a node moved by script keeps its old route. The agent's check, comparing each connector's endpoint ids before and after, passed with none detached while the board was visibly wrong. Re-assigning the endpoints, and detaching then re-attaching them, did not reroute. Putting the nodes back did. The render showed it.
- **A render taken right after a write showed the old state.** The board reported 24,161 px wide when its content was about 6,300. A render a minute later was right. The agent read the first one as a failed revert until it checked the size again.
- **A per-section direction was ignored.** In a top-down flowchart, `direction LR` inside two sections was dropped by the layout, and a redraw meant to be two rows came out as one column about 3,300 px tall. The diagram reference says to use per-section direction sparingly. It does not say the layout can drop it when edges cross sections.
- **A loop inside a section reversed its reading order, and a loop-back across the whole diagram ran along the forward path.** The draft-and-validate loop put the check to the left of the step before it, so that section reads right to left in all three versions. The "improve" arrow back to the saved template overlapped the forward row until it pointed at a duplicate of the end node, as the reference suggests for back-references. Three versions were drawn, and the reference says to stop after two.
- **The next diagram starts where the last one ended.** Diagrams are appended one after another to the right. The redraw was about 3,350 px wide, so its last shape sat 250 px inside the next diagram's section. It was found from coordinates and not by eye. One shape was moved below its neighbour, and its connector did not go stale this time.

What held: the board and its pages were read before anything was written. Every script that moved or deleted nodes named them, checked names and counts first, and stopped on a mismatch. The render was the final check.

What changed because of it: nothing in the residents. A candidate was logged as Q-69 in `campaigns/candidate-residents.md`, with the checks this session would have wanted before and after drawing. It has the same cause as the 2026-11-03 entry on tall screens reviewed at a size that hides the error (`../the-studio-is-tried-before-it-is-trusted/2026-11-03-comuna-role-screens-rtl-and-review-text.md`): the agent trusted what the tool reported and the render said otherwise.
