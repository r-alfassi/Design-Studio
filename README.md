# Design Studio

The visual-design process and the cross-project craft it draws on, such as RTL, platform norms and design-process skills, kept apart from any client engagement and any one project. A project imports `AGENTS.md`. The record in `.compass/` holds Design Studio's own intent and work.

This repo never accumulates client-identifying content. That was the specific drift that entangled Harness — a standing rule here, not a one-time cleanup.

## What's where

`standards/` holds binding cross-project design constraints selected by a
project. `mobile-design` sets the mobile visible-text floor and its validation
path.

| Directory | Holds |
|---|---|
| `AGENTS.md` | The spine a project imports: what loads first and where each kind of visual work goes. |
| `skills/` | Whole jobs carried to a result. Figma: `figma-sprint`, `figma-audit`, `figma-formalize`, `figma-pixel-fidelity`; meta: `skill-creator`, `figma-conversion-skill-builder`; and the web, mockup, brand and review crafts. Full index with "reach for it when": `skills/README.md`. |
| `frameworks/` | One judgment each, as questions and quality bars: `brand-strategy-foundations`, `ux-expert` (the 30 Laws of UX). |
| `standards/` | Binding rules a project adopts by naming them in its `DESIGN.md`: `mobile-design` (the mobile text floor), `studio-presentation` (the quiet kit for presenting work in Figma). |
| `templates/` | The required shape of a file or deliverable: `product-design`, `product-component`, `strategic-deck`, `ux-benchmark`, `video`, `figma-change-log`, `figma-implementation-contract`. |
| `tools/` | Scripts that produce what must be exact, such as `check-presentation-chrome.js`. |
| `references/` | This repo's own how-tos (tool set-up, FigJam board conventions). |
| `library/` | External, non-binding design and UX resources worth returning to. Governs nothing. |
| `STRUCTURE.md` | How Design Studio is organized and named, and how a resident is admitted. For people working on the repo. |
| `skills-lock.json` | Provenance and integrity for vendored third-party skills. |
| `.compass/` | The record: what Design Studio intends and what is in progress. |

## How a project links in

A project's own `DESIGN.md` cites the relevant convention here rather than duplicating it — the same split CULTURE.md holds with PRODUCT.md across this suite.

## Status

The Compass record governs the current intent and work. Design Studio remains a
passive knowledge repo, read and applied on demand rather than consulted as an
active agent. Principal is the steward; the Designer approves material changes.
